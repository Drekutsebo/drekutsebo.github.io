
# FPV Competition

Полноценное приложение для проведения соревнований FPV:
- публичная главная страница и общий рейтинг;
- вход волонтёров;
- импорт участников из CSV;
- отметка посещаемости;
- теоретический тест: 10 вопросов, 5 минут, одна попытка;
- ввод результатов симулятора и реальных полётов;
- серверный подсчёт рейтинга.

## Архитектура

- `frontend/` — React + TypeScript + Vite.
- `worker/` — Cloudflare Worker API.
- `shared/` — общие типы.
- Хранилище — JSON-файл в приватном GitHub-репозитории. Worker читает и обновляет его через GitHub Contents API. Записи используют SHA файла и повторные попытки при конфликте обновления.

> Важно: GitHub JSON подходит для небольшого мероприятия и умеренной нагрузки. Для большого числа одновременных операций лучше перейти на Cloudflare D1. Текущая реализация предотвращает простую перезапись устаревшей версии файла, но GitHub Contents API не является полноценной транзакционной БД.

## 1. Требования

- Node.js 20 или новее;
- npm;
- аккаунт GitHub;
- аккаунт Cloudflare.

## 2. Установка frontend

```bash
cd frontend
npm install
cp .env.example .env
```

В `.env` укажи URL Worker:

```env
VITE_API_URL=https://your-worker.your-subdomain.workers.dev
```

Для локальной разработки Worker обычно работает на `http://localhost:8787`.

Запуск:

```bash
npm run dev
```

Сборка:

```bash
npm run build
```

## 3. Создание приватного хранилища GitHub

1. Создай отдельный **приватный** GitHub-репозиторий, например `fpv-competition-data`.
2. Создай в нём файл `data.json` со следующим содержимым:

```json
{
  "version": 1,
  "participants": [],
  "attendance": {},
  "results": {},
  "testAttempts": {},
  "testSessions": {}
}
```

3. Создай GitHub Personal Access Token (fine-grained) с доступом только к этому репозиторию и разрешением **Contents: Read and write**.
4. Не добавляй токен в frontend, `.env` frontend или GitHub Pages.

## 4. Настройка Worker

```bash
cd worker
npm install
npx wrangler login
```

Открой `worker/wrangler.toml` и замени `YOUR_WORKER_NAME` и `YOUR_ALLOWED_FRONTEND_ORIGIN`.

Установи секреты:

```bash
npx wrangler secret put GH_TOKEN
npx wrangler secret put GH_OWNER
npx wrangler secret put GH_REPO
npx wrangler secret put VOLUNTEER_PASSWORD
npx wrangler secret put JWT_SECRET
```

Значения:
- `GH_TOKEN` — GitHub token из шага 3;
- `GH_OWNER` — имя владельца GitHub-репозитория;
- `GH_REPO` — имя приватного репозитория;
- `VOLUNTEER_PASSWORD` — общий пароль волонтёров;
- `JWT_SECRET` — длинная случайная строка минимум 32 символа.

`GH_BRANCH` и `GH_DATA_PATH` заданы в `wrangler.toml` и могут быть изменены там.

Развёртывание:

```bash
npx wrangler deploy
```

Для локального запуска:

```bash
npx wrangler dev
```

В локальном режиме секреты можно задать в `worker/.dev.vars` (этот файл не коммить):

```env
GH_TOKEN=github_pat_...
GH_OWNER=your-github-login
GH_REPO=fpv-competition-data
VOLUNTEER_PASSWORD=change-me
JWT_SECRET=replace-with-a-long-random-secret
```

## 5. Настройка frontend и публикация

В `frontend/.env` укажи адрес развёрнутого Worker. Для GitHub Pages используй обычную сборку Vite и настрой `base` в `vite.config.ts`, если сайт размещается не в корне домена.

```bash
cd frontend
npm run build
```

Содержимое `frontend/dist` можно опубликовать на GitHub Pages, Cloudflare Pages или другом статическом хостинге.

## 6. Импорт участников

Войди как волонтёр, открой «Посещаемость» и загрузи CSV. Формат:

```csv
ФИО;Группа
Иванов Иван Иванович;ИС-21
Петров Пётр Сергеевич;ИС-22
```

Поддерживаются разделители `;` и `,`. Первая строка может содержать заголовки `ФИО` и `Группа`. Кодировка — UTF-8. Импорт заменяет текущий список участников, поэтому загружай полный актуальный список.

## 7. Правила рейтинга

`Итого = тест + ворота симулятора + ворота реальных полётов`.

Незавершённый этап даёт 0. При равенстве:
1. выше результат теста;
2. выше результат реальных полётов;
3. ФИО по алфавиту.

## 8. Безопасность и эксплуатация

- Пароль волонтёров, JWT secret и GitHub token хранятся только в secrets Worker.
- Не публикуй `worker/.dev.vars`, токены или содержимое приватного хранилища.
- Публичный рейтинг показывает ФИО и группу. До публикации результатов организатор должен уведомить участников и обеспечить надлежащее основание для публикации этих данных.
- Делай резервные копии `data.json` до и после мероприятия.
- Тестовые вопросы и правильные ответы находятся на сервере; клиент получает только текст и варианты.
- Таймер, срок сессии, проверка одной попытки и подсчёт баллов выполняются сервером.
- Общий пароль означает, что действия волонтёров не привязаны к конкретным сотрудникам. Для персонального аудита потребуется индивидуальная авторизация.

## 9. Проверка после запуска

1. Открой frontend.
2. Войди с `VOLUNTEER_PASSWORD`.
3. Импортируй CSV участников.
4. Отметь одного участника.
5. Добавь результаты симулятора и полётов.
6. Проверь общий рейтинг в приватном окне.
7. Запусти тест участника и проверь, что повторный запуск блокируется.

Если Worker отвечает ошибкой, проверь его логи:

```bash
cd worker
npx wrangler tail
```
